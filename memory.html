Halogen 内存压缩测试memory compression test

压缩设置把 Halogen 的内存占用从 89.0 GiB 降到 74.2 GiB（省 14.8 GiB，约 17%），留给其他软件的内存从 25.3 GiB 增到 40.1 GiB。代价很小：生成速度慢 0.5%，读提示速度最多慢 1.8%（131K 长度）。两种设置下，内存都在启动时一次分配好，读 3 万 token 长提示时峰值不再上涨。服务器现在已按压缩设置运行。

The compressed settings cut Halogen's memory use from 89.0 GiB to 74.2 GiB (14.8 GiB saved, about 17%), raising the memory left for other software from 25.3 GiB to 40.1 GiB. The cost is small: decode is 0.5% slower and prompt reading at most 1.8% slower (at 131K). With either setting, memory is allocated once at start and does not rise while reading a 30K-token prompt. The server now runs with the compressed settings.

和 Strata 跑同一个模型对比：Halogen 读提示快约 4 倍、生成快约 2 倍，功耗相同，内存少占约 38 GiB。Strata 在这台机器上几乎占满内存。

Against Strata running the same model, Halogen reads prompts about 4× faster and decodes about 2× faster at the same power, using about 38 GiB less memory. Strata nearly fills this machine's memory.

速度Speed

压缩后速度变化都在 −3.6% 到 +0.7% 之间；两种设置都复现了 Halogen 官方数据。文档预计工作区减半会让读提示慢约 9%，实测只慢了 1.8–3.6%。

Every speed change with compression falls between −3.6% and +0.7%, and both settings reproduce Halogen's published numbers. The docs expect halving the workspace to slow prompt reading by about 9%; measured, it is only 1.8–3.6%.

建议Advice

日常使用压缩设置：多出 14.8 GiB 空闲内存，速度几乎不变。

Use the compressed settings day to day: 14.8 GiB more free memory at almost the same speed.

在这台机器上跑这个模型选 Halogen：比 Strata 快 2–4 倍，还留出约 40 GiB 内存给其他软件。Strata 运行时几乎占满内存，其他程序会被挤进交换空间。

For this model on this machine, pick Halogen: 2–4× faster than Strata with about 40 GiB left for other software. Strata nearly fills memory and pushes other programs into swap.

  • 压缩的取舍：缓存池减半后，同一时间只能保留一个 26 万 token 的超长对话；普通长度的多个对话不受影响。The trade-off: with the pool halved, only one 260K-token conversation fits at a time; several normal-length conversations are unaffected.
  • 换回默认设置的情况：需要同时保留多个超长对话，或要求输出与 16 位缓存逐字一致。When to switch back to default: you need several very long conversations at once, or output identical word for word to a 16-bit cache.
  • 还能再省（未测）：换 ht43 权重可再省约 8.4 GiB（需下载约 58 GB，质量损失未公布）；上下文减半到 131K 可再省约 2 GiB。More savings (untested): the ht43 weights would save about 8.4 GiB more (a ~58 GB download, quality loss unpublished); halving context to 131K saves about 2 GiB more.

测试方法与来源Method and sources

  1. 生成速度：Halogen 自带 bench serial,mtp 256 low 3（10 种提示 × 3 次，贪心解码）。Decode: Halogen's own bench serial,mtp 256 low 3 (10 prompts × 3 runs, greedy).
  2. 读提示速度：sweep -p 8192,32768,131072 -n 128，HALOGEN_PROMPT_CACHE=0 关闭提示缓存。Prompt speed: sweep -p 8192,32768,131072 -n 128, with HALOGEN_PROMPT_CACHE=0 to turn off the prompt cache.
  3. 内存：启动一个独立服务器，记录 Halogen 自报的内存明细、显卡 GTT/VRAM 和 /proc/meminfo；再发一个 30,023 token 的长提示，每 0.5 秒采样。Memory: a separate server instance, logging Halogen's own memory breakdown, GPU GTT/VRAM and /proc/meminfo; then one 30,023-token prompt, sampled every 0.5 s.
  4. 功耗与温度：每秒读 amdgpu 传感器的 PPT（芯片封装功耗）和 GPU 温度。Power and temperature: the amdgpu sensors' PPT (package power) and GPU temperature, read every second.
  5. 每种设置在同一台机器、同一天连续跑一遍；每次测试前正常关闭上一个服务器，并确认显卡内存已释放（≤ 0.3 GiB）。Each setting ran once, back to back on the same machine and day; before each test the previous server was shut down cleanly and GPU memory confirmed released (≤ 0.3 GiB).
  6. Strata 对比：llm-probe.sh 给两个服务器发完全相同的请求（3 个短提示各生成 256 token；8K/32K/131K 提示各生成 128 token；同一个 3 万 token 长提示），每个提示都是新的，提示缓存帮不上忙；同时每 0.5 秒记录 GTT、可用内存、功耗和温度。Strata 标准测试用 strata bench run（standard-v1）；它不接受其他服务器，所以用 replay-bench.py 把同样 9 个性能请求原样发给 Halogen。两个引擎轮流单独运行，切换前确认显卡内存已释放。Strata comparison: llm-probe.sh sends identical requests to both servers (3 short prompts with 256 tokens out; 8K/32K/131K prompts with 128 tokens out; one 30K-token prompt), every prompt new so no prompt cache helps, while logging GTT, free memory, power and temperature every 0.5 s.
